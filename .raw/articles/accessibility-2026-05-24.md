# Accessibility - Fluent 2 Design System

## Building for Diverse Experiences

"Solving for one and extending to many." Fluent components adhere to or exceed WCAG 2.1 AA.

## Structure, Hierarchy, and Navigation

Apply type ramp, formatting, color, dividers, and spacing for visual groupings. Section headings enable scanning. Use heading elements in logical, sequential order.

## Keyboard Navigation and Assistive Tech

Manage focus visibility. Focus follows a "z" pattern (left→right, top→bottom). Remain visible after temporary UI (dialogs) closes.

## Color (WCAG AA)

- Standard text: ≥ 4.5:1
- Large text (18.5px bold or 24px regular): ≥ 3:1
- Interactive + non-textual (icons): ≥ 3:1 against adjacent colors

## Responsive Layouts

Layouts must accommodate 400% zoom without horizontal scrolling (320px min) and 200% text zoom without clipping.

## Rich Media

Provide alt text for visuals. Make video captions customizable for contrast preferences.

## Meaningful Text

Plain, concise, consistent, descriptive language. Avoid complex terminology — supports skimming and non-native speakers.

## Code Standards

Logical, semantic code. Reference WAI-ARIA authoring practices.

## Design Accessibility Specs

Document focus order, screen reader annotations, semantic structure, interactions across devices. Tools: A11y - Focus Order Figma plugin, Accessible Design Toolkit.
