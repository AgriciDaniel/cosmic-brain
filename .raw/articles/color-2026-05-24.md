# Color - Fluent 2 Design System

## Overview

"Color is a tool used to express style, evoke emotion, and communicate meaning." The Fluent 2 system employs standardized palettes and intentional application to maintain consistency across experiences.

## Fluent Palettes

The design framework comprises three distinct palettes, each serving specific functions:

### Neutral Colors

These blacks, whites, and grays form the foundation of interfaces. They appear on surfaces, text, and layout elements, often indicating state changes in components.

**Visual Hierarchy**: Lighter neutrals on surfaces emphasize primary focus areas and guide user attention to the most important or useful sections of an interface.

### Shared Colors

Aligned across the Microsoft 365 suite, shared colors appear in high-value, reusable components like avatars, calendars, and badges. They enable quick mental recognition across products and should be used sparingly for accents.

In dark mode, these colors shift in saturation and brightness to reduce eye strain and meet accessibility requirements.

#### Semantic Colors

Specific shared palette selections communicate feedback, status, or urgency. "Semantic colors communicate at-a-glance information by building on real world associations, like red for danger, yellow for caution, and green for positive feedback."

**Usage guidelines**:
- Use for important messages conveying crucial information
- Avoid using them purely for decoration
- Pair with other indicators to reinforce context

### Brand Colors

Product distinction relies on dedicated brand colors across the M365 ecosystem. Each product—Teams, Word, Excel, PowerPoint, Outlook, and others—has its own color identity.

**Application principles**:
- Use to create visual prominence and anchor users within specific products
- Avoid overuse on large surfaces, which dilutes hierarchy

## Interaction States

Components typically darken through interaction stages: rest (lightest) → hover → selected (darkest). Focus states employ thicker container strokes rather than color changes to distinguish keyboard from mouse interactions.

*Note: Windows treats interaction states inversely, with controls becoming lighter upon interaction.*

## Accessibility Best Practices

1. Ensure perceivable contrast for low-vision and color-blind users
2. Enable personalized color schemes where possible
3. Accompany color with text, graphics, and other indicators to convey information multifacetedly

## Color Tokens

The token system stores palette values as context-agnostic globals. Alias tokens provide contextual guidance, simplifying color selection without requiring hex code lookups and improving design-to-development workflows.
