# Onboarding - Fluent 2 Design System

## Overview

Not a singular event — "different teaching points in a user's journey and offer information when people are ready to take it in."

## Principles

- **Relevant** — within context of closely related tasks
- **Non-distracting** — never a barrier to primary goal
- **Optional** — users can exit and return
- **Benefit-focused** — upfront clarity about personal benefits
- **Coherent** — standard Fluent components for predictability

## Scenarios and Goals

- **Welcome** — reassure users; one-time simple screens/banners/modals emphasizing benefits
- **Orient** — show features in context (empty states, teaching popovers)
- **Notify** — alert about new/changed functionality (banners, popovers, toasts)
- **Explain** — embed hints within UI; concise text + clear CTA
- **Take action** — first-run experiences, carousels, multi-step flows in drawers

## Content Guidelines

- **Action-oriented language** — active voice; CTAs complete "I want to…"
- **Accessible support** — tooltips, learning links, teaching popovers. Use "Need help?" not "Stuck?"
- **Clear expectations** — "This takes 2–3 minutes"
