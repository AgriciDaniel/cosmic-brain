You request the payment rules in the toolbar Payment day types. The payment rules specify which parts

of the working time are offset against which wage type.

Selection criteria

The application provides the following selection criteria:

Day type, valid from

The number and the validity start date of the payment day type are transferred when the payment

rules are called.   Payment day types . If both fields are empty, the payment rules for all payment

day  types  are  displayed  and  you  can  check  which  wage  types  are  used  for  which  payment  day

types.

Field description for the tab "Payment rule"

Wage type

Wage type that is to be generated by the rule.

Processing

Processing of the payment rule (until target time is reached, overtime, working time, catch-up time,

fixed  time,  core  time  violation,  working  time  before  general  start,  working  time  after  general  end,

paid break, on-call duty). Payment rules are described in the next chapter.

Comment

You can enter in this field a comment on the payment rules.

Calculate overtime type

Do not post

If the time should not be posted, then the time of the specified wage type is not generated.

Hide

You can specify if this rule should hide other rules for target times or overtime.

Time type

bonus is already being paid, or that the night bonus is greater for overtime than during the general

working hours (target time).

Payment rules

Shift type

Restriction  of  the  payment  rule  for  a  certain  shift  type.    The  entry  *  (asterisk)  stands  for  all  shift

types.

Process payment rule on the previous day

The field is only valid for payment rules of the type "Fixed time from ... to ..." and controls whether

the payment rule is also valid on the previous day.  For example: If a night shift begins on the day

before a public holiday and is assigned to the previous day for accounting purposes, you can use

this  button  to  calculate  the  public  holiday  bonus  without  having  to  create  your  own  payment  day

type for the day before the public holiday.

To additionally process payment rules on the next day

The field is only valid for payment rules of the type "Fixed time from ... to ..." and controls whether

the  payment  rule  is  also  valid  on  the  next  day.    For  example:  If  a  night  shift  begins  on  a  public

holiday  and  is  assigned  to  the  following  day  for  accounting  purposes,  you  can  use  this  button  to

calculate the public holiday bonus without having to create your own payment day type for the day

after the public holiday.

The planned payment day type of the previous and next days is processed for the two buttons

"Process  payment  rule  on  previous  day"  and  "Process  payment  rule  on  next  day".  This  is

independent of which payment day category is actually used on the previous and next day due

to manual editing or shift type payments.

Payment rules

Up to the target time being reached

This  payment  rule  says  that,  until  the  planned  working  time  has  been  reached,  the  employee's

working time should be posted with the specified wage type.

Undertime

If  the  payment  day  type  is  used  as  overtime  type,  then  you  can  see  on  top  the  processing  of

"Undertime".    This  processing  determines  that  the  total  undertime  in  a  period  for  the  overtime

calculation is offset against the specified wage type on the 1st day of the period. Undertime is the

time a person lacks to reach the target time within a calculated period. Example: A weekly planned

working time of 40 hours and an actual working time of 37.5 hours results in 2.5 hours of undertime,

which is posted to a wage type using this payment rule.

Payment rules

Overtime from …

This  is  used  to  post  overtime.    It  can  be  specified  here,  after  what  duration,  overtime  should  be

posted with the specified wage type. Example: You can specify that the first two hours of overtime

are posted with a 25% bonus, between two and five hours overtime with 50% bonus and after five

hours  no  overtime  is  posted  at  all.  In  this  payment  rule,  you  can  choose  in  the  lower  part  of  the

window whether the time is not to be posted (that is, it is discarded, the specified wage type is not

created) or whether the overtime is to be calculated using the overtime category for payment day

types. In this case, the basis of the allocation of overtime is the overtime type specified in the HR

master  data,  in  which  the  rules  for  the  allocation  of  overtime  and  undertime  can  be  found.  The

wage type for the planned time must be specified as the wage type for the target time, so that for

overtime compensation of more than one day, the wage type ensures that undertime on one day is

compensated with overtime on another day.

Working time from …

This processing is similar to the processing of "Overtime from", but the period to be entered refers

to the total  working time.  You can only use this payment rule to offset times once the target time

has been completed. If a time is entered, which is smaller than the target time, then this rule only

applies once the target time has been reached.

Fixed times from … to

You can use this payment rule to specify the wage type for a specific period of time of the day. Late

and night shift bonuses can be posted in this way. Times that extend past midnight must be added

to 24:00 hours (example: a booking of 23:00 to 2:00 = fixed time from 23:00 to 26:00). You can also

select at the bottom of the window, whether this rule should hide other rules for target time or

overtime.

In the bottom line, you can also specify whether the rule should relate to the period of the target

time, the overtime or both. Example: You can specify that late bonuses are no longer paid, if an

overtime bonus has been paid, or that the night bonus is greater for performed overtime than during

the general working hours (target time).

Night surcharges are configured separately for the early shift and night shift:

While for the night shift, you can store a rule from 8h to 30h, you must create a rule from 0h to 6h

for the early shift if someone has started during the time when a night surcharge is to be posted.

Compensation time to …

Using this payment rule, you can post compensation time, which is mainly required in Switzerland.

This  means,  that  the  first  15  minutes  of  working  time  can  be  credited  to  a  working  time  account

every day. Only after these 15 minutes, the working time is counted as part of the target time. When

this type is used you should note that the compensation to be posted may not be greater than the

target  time  from  the  working  time  day  type  and  that  at  least  one  payment  rule  “Until  target  time

reached” must exist.

Payment rules

Core time violation

A  rule  of  this  type  has  the  effect  that  the  core  time  violations  of  an  employee  are  posted  to  the

specified wage type.

You only use the rule for the "Core time violation" to calculate labor time.  If several rules of this

type  exist,  the  rule  for  core  time  violations  is  used,  for  which  the  smallest  wage  type  is

calculated.

Working time before skeleton time start, working time after skeleton start

These  rules  have  the  effect  that,  for  flextime  workers  or  flexible  shift  workers,  the  working  time

outside  the  skeleton  time  is  posted  to  the  specified  wage  type.  Use  the  Hide  button  to  specify

whether time posted in this way counts as working time or if it is hidden when the working time is

calculated.

Paid break

With this payment rule, the duration of a paid break which is specified in the working time day type

can be posted to a wage type.

On-call duty, stand-by duty

Both payment rules are only available if you have a license for an additional function On-call duty.
