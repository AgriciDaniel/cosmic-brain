Escalation Management - Summary
1 Escalation Management - Summary
Summary
HYDRA Escalation Management provides a framework of functions for forwarding events occurring or
entered in HYDRA to individual users or user groups in real time. In this context, Escalation Management
actively undertakes notification steps.
After sending a notification, Escalation Management monitors the time it takes the notified person to
acknowledge the notification and the time until the escalation is closed. Escalations can be forwarded to
other users or user groups during processing.
Implementation Notes
You use the HYDRA escalation management module if you want to be notified actively and in realtime
about specific events in the production environment to avoid breakdowns through immediate reaction and
to increase efficiency as well as productivity.
You use the HYDRA escalation management module if you want to monitor response times to
escalations of certain departments or people.
Integration
HYDRA Escalation Management provides a framework for further HYDRA components to be able to
forward and trace back triggered events.
To be able to inform people, the escalation management module refers to the HYDRA user administration
(see the SIS-MWV component) as well as to the HR master data defined in HYDRA (see SIS-IPS
component).
If the collection and maintenance of labor times (PZE-EPP) component is in use, the escalation
management allows for the recipient to be determined subject to the currently recorded attendance time
in the company.
Notifications may also be sent by e-mail as the module is integrated with the local mail server.

Structure of components
The Escalation Manager is the heart of Escalation Management. It is a continuously running process
(hyeskmgr.out/hyeskmgr.out) which receives events generated by individual applications and checks
whether escalations have been configured for these events. If this is the case, the Escalation Manager
creates messages for users or user groups according to the configuration and for the communication
technologies that are stored.
The individual HYDRA applications generate the events. The reasons for events may be, for example,
errors or exceptional situations (e.g. hard disk is full). But events can also be the result of "normal" data
collection and processing in HYDRA (e.g. if a new machine status is entered at the terminal).

In these cases, the applications create an event. This event is characterized by a unique designation that
applies for the entire system. The applications also transfer data to the Escalation Manager. The event
determines the type and scope of the transferred data. In many cases, this data can be used as condition
in the configuration, and it may also be integrated in the messages to be sent.
Not all applications can generate a message on their own in all error cases or exceptional situations (e.g.
a terminal cannot report that it is currently offline). For this reason, the Escalation Manager provides
another component that is called Escalation Agent. The Escalation Agent cyclically checks the current
status of values that have been assigned to cyclical monitoring. The Control Agent sends the affected
event  to  the  Escalation  Manager  if  violations  are  detected  during  monitoring.  Once  per  hour  the
Escalation Manager updates its internal list of configured events with the cyclical events stored within the
database.
Available Escalations
The HYDRA Escalation Management, as it is described in this documentation, is an integral part of the
HYDRA MESWeaver. Escalations are triggered by individual applications which are to be assigned to the
individual HYDRA modules. Furthermore, available escalations depend on the different release versions.
For this reason, please find below a list indicating the available escalations for the corresponding release
and module in separate documents.
