FORM Datenanlage - FAQ

 

WinLine Objekte

Frage:       Welche WinLine Objekte werden bei der "FORM Datenanlage" unterstützt?

 

Antwort:    Bei folgenden Objekten steht die FORM Datenanlage zur Verfügung:

 

ü  Personenkonten*

ü  Sachkonten*

ü  Interessenten*

ü  Artikel*

ü  Arbeitnehmer*

ü  Kontakte

ü  Anlagen

ü  Kostenstellen

ü  Kostenarten

ü  Kostenträger

ü  Projekte

ü  Mitarbeiter*

 

Hinweis:    * => Es können auch Zusatzfelder aus den FORM-Datensätzen zugeordnet werden

 

Neuanlage oder Update

Frage:       Handelt es sich bei einer "FORM Datenanlage" immer um eine Neuanlage?

 

Antwort:    Nein! Ob es sich bei der "FORM Datenanlage" um eine Neuanlage oder um ein Update von bestehenden Stammdaten handelt, ist von mehreren Faktoren abhängig:

 

ü  FORM-Feld wird mit Objekt-Keyfeld (z.B. Artikelnummer) verknüpft

ü  Ist FORM-Feld gefüllt und Objekt-Keyfeld nicht, so wird der Inhalt des FORM-Feld für eine Neuanlage genutzt

 

ü  Ist FORM-Feld nicht gefüllt und Objekt-Keyfeld ebenfalls nicht, so wird eine Neuanlage durchgeführt

 

ü  Ist Objekt-Keyfeld gefüllt, so findet immer ein Update für das Objekt des Objekt-Keyfelds statt

 

ü  Kein FORM-Feld ist mit dem Objekt-Keyfeld (z.B. Artikelnummer) verknüpft

ü  Ist Objekt-Keyfeld nicht gefüllt, so wird eine Neuanlage durchgeführt

 

ü  Ist Objekt-Keyfeld gefüllt, so findet ein Update für das Objekt des Objekt-Keyfelds statt

 

Nummernvergabe

Frage:       Woher kommt die Nummer bei einer Neuanlage?

 

Antwort:    Es gibt unterschiedliche Varianten, woher die Nummer stammen kann:

 

ü  1. Aus dem verknüpften FORM-Feld

ü  2. Aus der EXIM-Vorlage

ü  3. Wird automatisch von der WinLine vergeben (entspricht Taste "+" im jeweiligen Stammdatenprogramm)

 

Frage:       Muss immer eine fixe Nummernvorgabe genutzt werden?

 

Antwort:    Nein! Es kann auch mit einem Nummernkreis oder einem Nummernbereich gearbeitet werden:

 

ü  Nummernkreis => "Name des Nummernkreises" und ein "+"

ü  D+

ü  Fitness+

ü  …

 

ü  Nummernbereich => "Startnummer" und ein "+"

ü  40000+

ü  75000+

ü  …

 

FORM-Schlüsselobjekt

Frage:       Braucht man in der FORM auch ein "FORM-Schlüsselobjekt", d.h. einen eindeutigen Key?

 

Antwort:    Das hängt davon ab, wie man arbeiten möchte und woher die Daten der FORM stammen:

 

ü  FORM-EXIM

ü  Wird nur 1x und nie wieder importiert, dann benötigt der FORM-Datensatz keinen eindeutigen Key.

ü  Möchte man in die gleiche FORM mehrmals importieren und dabei die Daten "updaten", dann muss es einen eindeutigen Schlüssel geben.

 

ü  FORM-DataCenter
Soll in der Folge im DataCenter auch aktiv gearbeitet um z.B. etwas anzupassen?

 

ü  Ja => Dann wäre das FORM-Schlüsselobjekt anzuraten, um schnell zum Datensatz zu kommen

ü  Nein => Zur Not gibt es auch die VCR-Buttons

 

Beispiel:

Man erhält von seinem Lieferanten 1x pro Monat einen Artikelkatalog, wobei auch zum Teil neue Artikel hinzukommen. Der Lieferant arbeitet mit "seiner" Artikelnummer; intern soll aber ein eigener Nummernkreis verwendet werden.

 

ü  FORM-Schlüsselobjekt

Wird mit Lieferantenartikelnummern gefüllt

Für einen Abgleich beim erneuten Import notwendig

 

ü  FORM-Eingabefeld

ü  Verknüpft mit Artikelnummer

ü  Hinterlegung einer Startnummer oder eines Nummernkreises (die Angabe könnte auch über die EXIM-Vorlage erfolgen)

 

ü  WinLine-Objektauswahl

ü  WinLine-Objekt "Artikel"

ü  Wird nach Stammdaten-Übernahme mit WinLine Artikelnummer versehen
