# Elsa Security

Security configuration for [[entities/Elsa Workflows]] spans authentication, authorization, tokenized bookmark URLs, CORS, rate limiting, secrets management, and network security. Elsa provides a modular identity system and integrates with standard ASP.NET Core security middleware.

---

## Authentication Options

Elsa supports four authentication modes, configured through the `Elsa.Identity` module:

### 1. No Authentication (Development Only)

For local development and testing. Must be gated behind environment checks:

```csharp
if (builder.Environment.IsDevelopment())
{
    Elsa.Api.Common.Options.EndpointSecurityOptions.DisableSecurity();
}
```

> [!danger] Production Risk
> Never deploy with authentication disabled. An unauthenticated Elsa instance exposes full workflow management, execution, and data access to anyone who reaches the endpoint.

### 2. Elsa.Identity (Built-In)

Built-in identity with API keys, JWT tokens, and role-based access:

```csharp
builder.Services.AddElsa(elsa =>
{
    elsa
        .UseIdentity(identity =>
        {
            identity.UseConfigurationBasedIdentityProvider();
        })
        .UseDefaultAuthentication();
});
```

Configure users and roles in `appsettings.json`:

```json
{
  "Elsa": {
    "Identity": {
      "Providers": [
        {
          "Type": "ApiKey",
          "Options": {
            "ApiKeys": [
              { "Key": "${API_KEY_ADMIN}", "Roles": ["Admin"] }
            ]
          }
        },
        {
          "Type": "Jwt",
          "Options": {
            "Issuer": "elsa-workflows",
            "SigningKey": "${JWT_SIGNING_KEY}",
            "ValidateLifetime": true
          }
        }
      ]
    }
  }
}
```

### 3. External OIDC Providers

Elsa integrates with any OpenID Connect provider for SSO. Supported providers include:

| Provider | Type |
|----------|------|
| Microsoft Entra ID (Azure AD) | OIDC + OAuth 2.0 |
| Auth0 | OIDC + JWT Bearer |
| Keycloak | OIDC |
| Okta | OIDC |
| Google Identity | OIDC |
| Any OIDC-compliant IdP | Generic OIDC |

**Example: Azure AD integration:**

```csharp
builder.Services
    .AddAuthentication(OpenIdConnectDefaults.AuthenticationScheme)
    .AddOpenIdConnect(options =>
    {
        options.Authority = "https://login.microsoftonline.com/{tenant-id}";
        options.ClientId = "{client-id}";
        options.ClientSecret = "{client-secret}";
        options.ResponseType = "code";
        options.SaveTokens = true;
        options.Scope.Add("openid");
        options.Scope.Add("profile");
        options.Scope.Add("email");
    });

builder.Services.AddElsa(elsa =>
{
    elsa.UseDefaultAuthentication()
        .UseWorkflowManagement()
        .UseWorkflowRuntime()
        .UseWorkflowsApi();
});
```

### 4. Custom Authentication

Implement custom `IAuthenticationHandler` or use standard ASP.NET Core authentication schemes. Elsa's authorization layer works with any compatible `ClaimsPrincipal`.

## Tokenized Bookmark Resume Security

Bookmark resume tokens (generated by `GenerateBookmarkTriggerUrl`) allow external systems to resume suspended workflows. These tokens require several security controls:

### Time-to-Live (TTL)

| Use Case | Recommended TTL |
|----------|-----------------|
| Webhook callbacks | 5-15 minutes |
| Email approvals | 24-72 hours |
| SMS/Push notifications | 1-4 hours |
| Document signing | 7-30 days |

### Single-Use Semantics (AutoBurn)

Enable `AutoBurn` on bookmarks to delete them after the first successful resume, preventing replay attacks:

```csharp
var bookmark = context.CreateBookmark(new CreateBookmarkArgs
{
    Name = "ApprovalBookmark",
    Payload = new { ApprovalId = approvalId },
    AutoBurn = true,
    Callback = OnResumeAsync
});
```

### Additional Controls

- **Revocation**: Cancel workflows or maintain a distributed revocation list (Redis) for leaked tokens
- **Rate limiting**: Apply per-IP rate limits (100/min default for resume endpoints)
- **Audit logging**: Log all resume attempts with BookmarkId, SourceIp, success/failure
- **Token integrity**: Use HMAC signatures on token payloads
- **Least privilege**: Tokens should grant minimal permissions -- never embed credentials or full workflow state

> [!info] Token Expiration Behavior
> Expired tokens return `401 Unauthorized`. Consumed bookmarks return `404 Not Found`. Rate-limited requests return `429 Too Many Requests` with a `Retry-After` header.

## CORS Configuration

For browser-based clients (e.g., Elsa Studio), configure CORS with specific origins:

```csharp
builder.Services.AddCors(options =>
{
    options.AddPolicy("ElsaCors", policy =>
    {
        policy
            .WithOrigins("https://studio.example.com")
            .WithMethods("GET", "POST", "PUT", "DELETE")
            .WithHeaders("Content-Type", "Authorization");
    });
});
```

> [!warning] CORS Rules
> Never use `AllowAnyOrigin()` in production. For server-to-server webhooks, CORS is not required -- it is a browser-only security feature.

## Secrets Management

Never commit secrets to source control. Use environment variables or secret managers:

- **Azure Key Vault**: `builder.Configuration.AddAzureKeyVault()`
- **AWS Secrets Manager**: via `Amazon.SecretsManager.Extensions.Configuration`
- **User Secrets** (development): `dotnet user-secrets set "ApiKey" "value"`
- **Environment variables**: `${VARIABLE}` placeholders in config files

## Production Hardening Checklist

- [ ] HTTPS enforced (HTTP to HTTPS redirect)
- [ ] TLS 1.2+ with strong ciphers
- [ ] Valid SSL certificate (not self-signed)
- [ ] Security headers (HSTS, X-Frame-Options, X-Content-Type-Options)
- [ ] Rate limiting enabled for resume endpoints
- [ ] CORS whitelist locked down
- [ ] Authentication enabled and properly configured
- [ ] Secrets managed via secure vault (not config files)
- [ ] Audit logging enabled for all auth events
- [ ] IP allowlisting configured for internal endpoints
- [ ] Regular key rotation (API keys quarterly, JWT signing keys annually)
