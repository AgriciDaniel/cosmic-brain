# Fluent 2 Handoffs

A handoff is a user's transition between workflow stages — within an app or across M365. "Keep important content and provide the right tools and support users need to pick up where they left off."

## Three Principles

- **Guide seamlessly** — Copilot directs to the next logical step
- **Maintain context** — useful info transfers, noise is removed
- **Unify experiences** — cross-endpoint handoffs feel intentional and user-initiated

## Copilot's Five Roles

1. **Read** content for structure and key points
2. **Reformat** for the destination application
3. **Improve** (formatting, tone, summarization)
4. **Recommend** the optimal application for the user's goal
5. **Learn** preferences to refine future suggestions

## User Intent Levels

| Intent | Signal | Response |
|--------|--------|----------|
| **Strong** | Specific, goal-oriented | Confident next-step suggestion |
| **Semi-formed** | Partial clarity, exploring | Clarification support |
| **Loose** | Brainstorming, no endpoint | Communicate possibilities |

## Visual Patterns

- Chat responses
- **Artifacts** — editable rich content
- **Entities** — M365 file representations
- Side-by-side viewing
- Inline modules within hub pages

## CTA Vocabulary

| Phrase | Meaning |
|--------|---------|
| **Create…** | Build new content from existing material |
| **Open in…** | Access existing content without transformation |
| **Continue in…** | Move to deeper functionality elsewhere |
| **Try in…** | Experimental exploration of outputs |

System message format: **"Copilot [past-tense verb] [object] [in/from] [App Name]."**
